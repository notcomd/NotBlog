## 1. 需求分析与功能拆解

### 1.1 核心功能矩阵

| 模块 | 功能 | 优先级 | 说明 |
|------|------|--------|------|
| **圈子 Circle** | 创建/编辑/解散圈子 | P0 | Discord 式"服务器"：圈主 + 管理员 + 成员 |
| | 邀请制加入 | P0 | 邀请码 / 邀请链接 / 按用户直邀（确认后加入），三者均可撤销、有过期时间 |
| | 成员管理 | P0 | 圈主可设管理员、移除成员、转移圈主 |
| | 圈子信息 | P0 | 名称、描述、头像、成员数 |
| **帖子发布** | 圈子内发帖 | P0 | 复用 Tweet 聚合根：图文 / 视频 / 链接 / 话题标签 |
| | 全局发帖 | P0 | 保持现有微博式审核流（Pending→Approved） |
| | 圈子帖免审核 | P0 | 圈子内直接发布（Approved），契合"轻松氛围"；全局帖保持审核 |
| **话题 Topic** | 创建话题 | P0 | 全局轻量标签，任何用户可创建 |
| | 帖子打话题 | P0 | 一篇帖子可关联多个话题 |
| | 按话题浏览 | P0 | 话题聚合页 + 帖子数统计 |
| **社区互动** | 点赞 / 评论 / 收藏 | P0 | 完全复用现有 Tweet 互动能力（InteractionType.Like/Favorite + Comment） |
| | 关注 / 粉丝 | P0 | 全局关注关系，聚合"关注 Feed" |
| **实时在线** | 圈子频道实时推送 | P0 | SignalR：新帖 / 新评论 / 点赞 / 成员变动实时广播到 `circle:{id}` 频道 |
| | 通知 | P0 | 复用 TweetNotification：被邀请、入圈、新帖、新粉丝 |
| **扩展预留** | AI 机器人 / MCP | P1 | ICommunityEventPublisher 领域接口 + No-op 默认实现，预留 RabbitMQ / Webhook 接入 |

## 2. 核心设计决策

| # | 决策点 | 结论 |
|---|--------|------|
| D1 | 帖子模型 | **复用 Tweet 聚合根**，扩展 `CircleGuid`（可空，圈子帖）与 `TopicGuids`（JSON 列）；媒体/评论/点赞/收藏/通知全部复用 |
| D2 | 圈子 vs 话题 | **并存**：圈子=邀请制成员容器（Discord 服务器）；话题=全局轻量标签（类似 #话题） |
| D3 | 邀请制 | 邀请码（6 位，全局唯一）+ 邀请链接（token）+ 按用户直邀（对方确认）；圈主/管理员可生成与撤销，默认 7 天有效期 |
| D4 | 关注范围 | **全局关注**（微博式），独立于圈子成员关系；关注 Feed 仅聚合全局（非圈子）帖 |
| D5 | 实时性 | 新建 `CommunityHub`（SignalR），成员订阅 `circle:{id}` 频道；复用 Redis 连接管理与 JWT 认证 |
| D6 | AI/MCP 扩展 | `ICommunityEventPublisher` 领域接口（默认 No-op 实现），所有圈子事件统一出口；后续可接 RabbitMQ/Webhook/机器人订阅，不侵入业务代码 |

### 2.1 圈子帖 vs 全局帖规则

| 维度 | 全局帖（CircleGuid = null） | 圈子帖（CircleGuid ≠ null） |
|------|--------------------------|---------------------------|
| 状态流转 | Draft → Pending → Approved/Rejected | 发布即 Approved（免审核） |
| 可见性 | Public/Followers/Private 规则 | 仅圈子成员可见（作者本人始终可见） |
| 时间线/热门 | 进入 | 不进入（独立圈子 Feed） |
| 评论/点赞 | 无额外限制 | 仅圈子成员可互动 |
| 话题 | 可选 | 可选 |

## 5. 实时通信设计

### 5.1 CommunityHub（/CommunityHub）

```
[Authorize] Hub 方法：
  JoinCircle(Guid circleGuid)   — 校验成员身份后加入 SignalR 群组 "circle:{id}"
  LeaveCircle(Guid circleGuid)  — 离开群组
```

客户端接口 ICommunityClient（服务端 → 客户端事件）：

| 方法 | 载荷 | 触发时机 |
|------|------|----------|
| PostPublished | CirclePostDto | 圈子新帖（发布即推送到频道） |
| CommentAdded | CommentDto + TweetGuid | 圈子帖新评论 |
| PostLiked / PostFavorited | {TweetGuid, UserGuid, LikeCount} | 圈子帖点赞/收藏 |
| MemberJoined | CircleMemberBriefDto | 新成员加入 |
| MemberLeft / MemberRemoved | {CircleGuid, UserGuid} | 成员离开/被移除 |
| InvitedToCircle | {CircleGuid, InviteGuid} | 被邀请（推送给个人） |

### 5.2 推送链路

```
Command (发布圈子帖/评论/点赞)
  └─▶ 聚合根 AddDomainEvent(CirclePostPublishedEvent / CommentAddedEvent / TweetInteractionEvent)
        └─▶ NotMediator 分发（SaveEntitiesAsync 内）
              └─▶ DomainEventHandler
                    ├─▶ CommunityDeliveryService.PushToCircleAsync(circleId, ...)
                    │     └─▶ IHubContext<CommunityHub>.Clients.Group("circle:{id}")...
                    └─▶ ICommunityEventPublisher.PublishAsync(envelope)  // AI/MCP 扩展出口
```

成员身份校验：Hub JoinCircle 与圈子 Feed/互动接口统一走 `CommunityAccessGuard`。

## 6. AI 机器人 / MCP 扩展接口

### 6.1 ICommunityEventPublisher（领域层抽象）— 已接入 RabbitMQ

```csharp
public interface ICommunityEventPublisher
{
    /// <summary>发布一条社区事件（新帖/评论/入圈/关注...）</summary>
    Task PublishAsync(CommunityEventEnvelope envelope, CancellationToken ct = default);
}
```

已实现的两个实现，通过配置切换（`appsettings.json` → `CommunityEventBus:Enabled`）：

1. **RabbitMqCommunityEventPublisher（已接入，Enabled=true 时启用）**
   - 链路：领域事件 → `CommunityEventEnvelope` → `CommunityEventEnvelopeIntegrationEvent`
     （`[EventBusName("CommunityEvent.Published")]`）→ `IEventBus.PublishAsync`
     → RabbitMQ Direct exchange `notcomd_event_bus`（docker-compose 的 rabbitmq 服务）；
   - 统一信封设计：所有社区事件走同一路由键，订阅方按 `EventType` 字段分派
     （如 `circle.post.published` / `circle.member.joined` / `user.followed`），无需为每种事件单独建队列；
   - 容错：发布失败仅记录日志，不影响业务主流程；需要不丢事件时可启用 Eventbus.Outbox（EfCoreOutboxStore）；
   - 连接来源：DEBUG 读 `EventBus` 配置节手动 ConnectionFactory；Release 走 Aspire `AddRabbitMQClient("EventBus")` 服务发现。
2. **DefaultCommunityEventPublisher（默认，No-op）**：仅记录日志，保证零外部依赖可运行。

后续可扩展路径：
  1. **Webhook 实现**：按圈子配置推送 HTTP 回调；
  2. **机器人命令**：后续在 Command 层新增 `IBotCommand` 通道，机器人以服务账号（ServiceAccount Guid）调用同一套命令；
  3. **AI 机器人 / MCP 网关**：订阅 `notcomd_event_bus` exchange 的 `CommunityEvent.Published` 消息即可消费全部社区事件流。

### 6.2 CommunityEventEnvelope

```csharp
public sealed record CommunityEventEnvelope(
    string EventType,        // 如 "circle.post.published"
    Guid CircleGuid,         // 可能为空（全局事件）
    Guid ActorGuid,          // 触发者
    Guid? TargetGuid,        // 目标（帖子/评论/用户）
    string? PayloadJson,     // 附加载荷（序列化 JSON）
    DateTimeOffset OccurredAt);
```

所有圈子/话题/关注领域事件在 DomainEventHandlers 层统一转换为 envelope 发布，业务代码零侵入。

## 7. 后端业务逻辑实现

### 7.1 圈子聚合（Circle.cs）

- 私有 `_members` 列表（与 Group 一致），`MemberCount` 冗余计数；
- 方法：`Create`（圈主自动成为 Owner 成员）、`UpdateInfo`、`Dissolve`、`AddMember`（上限校验/重复校验/触发 CircleMemberJoinedEvent）、`RemoveMember`、`BanMember`、`SetAdmin`/`UnsetAdmin`、`TransferOwnership`、`IsMember`、`GetMember`；
- 领域事件：CircleCreatedEvent、CircleDissolvedEvent、CircleMemberJoinedEvent、CircleMemberLeftEvent、CircleMemberRemovedEvent、CircleOwnerTransferredEvent、CircleMemberRoleChangedEvent。

### 7.2 邀请聚合（CircleInvitation.cs）

- `CreateCode`（生成全局唯一 6 位码，重试防碰撞）、`CreateLink`（token）、`CreateDirect`（指定用户）；
- `Accept`（校验 Pending + 未过期 → Accepted，由命令层完成入圈）、`Revoke`、`IsExpired`；
- 邀请码加入：Code 查邀请 → 校验 → Circle.AddMember；
- 直邀加入：InviteeGuid == 当前用户 + Pending + 未过期。

### 7.3 话题（Topic.cs）

- `Create(name, description, creator)`：名称唯一（仓储校验）；
- `IncrementPostCount` / `DecrementPostCount`（帖子删除时，本期实现增量即可）；
- 发帖话题校验：TopicGuids 全部存在且 IsActive（仓储 `GetExistingAsync`）。

### 7.4 关注（UserFollow.cs）

- `Create(follower, followee)`：禁止关注自己、禁止重复关注；
- 统计：关注数/粉丝数由查询层 Count 得出（无冗余列，规模小时足够）。

### 7.5 圈子发帖命令（CreateCirclePostCommand）

- 复用 CreateTweetCommand 的媒体解析逻辑（FileDev gRPC 校验归属 + 元数据）；
- 校验：发帖人是圈子成员；话题存在；
- `Tweet.Create(..., circleGuid, topicGuids)` → `tweet.PublishInCircle(circleGuid)`（免审核直接 Approved）；
- 触发 `CirclePostPublishedEvent`（推送 + 通知 + 事件总线）。

### 7.6 访问控制（CommunityAccessGuard）

```
EnsureCircleMemberAsync(circleRepo, circleGuid, userId)      — 圈子 Feed/详情
EnsurePostInteractionAllowedAsync(tweet, userId, memberRepo) — 圈子帖评论/点赞/收藏
 规则：tweet.CircleGuid == null → 放行；否则必须为圈子成员（作者本人放行）
```

## 8. 异常处理与日志记录策略

- 业务异常：`ArgumentException` / `InvalidOperationException` / `KeyNotFoundException` / `UnauthorizedAccessException`，命令层捕获已知异常直接抛出（与现有命令一致），API 层映射为 `ApiResponse` 4xx/5xx；
- 圈子无权限访问统一抛 `UnauthorizedAccessException` → 403；
- 日志：每个命令/查询遵循现有"开始/成功/失败"三段式 `LogInformation/LogError`，关键路径（发帖、入圈、邀请）额外记录审计日志；
- 事件处理器一律 try-catch 包裹（推送/通知失败不影响主流程）。

## 11. 决策记录

| # | 决策 | 理由 |
|---|------|------|
| 1 | 复用 Tweet 作帖子模型 | 图文/视频/评论/点赞/收藏/通知全复用，工作量最小、体验一致 |
| 2 | 圈子帖免审核 | 契合"氛围轻松"定位；全局帖保留审核流 |
| 3 | 圈子帖仅成员可见 + 成员才可互动 | 邀请制社区的私密性基础 |
| 4 | 关注独立于圈子 | 关注是"人"维度，圈子是"内容容器"维度，正交设计 |
| 5 | 话题用 JSON 列 | 轻量社区规模下避免关联表复杂度；LIKE 查询够用 |
| 6 | 事件出口抽象为 ICommunityEventPublisher | AI/MCP 零侵入接入；RabbitMQ 实现已落地（CommunityEventBus:Enabled 开关），默认 No-op 保证无外部依赖 |
